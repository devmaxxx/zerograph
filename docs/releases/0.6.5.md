# zerograph 0.6.5

The release notes for the GitHub release page. The why behind each change is in the docs each line
links to.

## Breaking

- **`zerograph watch` is removed.** It ran the same poll as `serve` without answering anything, and
  every MCP tool now refreshes before it answers, so it was one more process per worktree and one
  more writer. A script or service that starts `zerograph watch` now fails with an unknown-command
  error: start `zerograph serve` instead, which polls the tree between questions with the same
  `--every` and `--batch`. `serve` exits after `--idle` seconds without a question (30 minutes by
  default), so a poller meant to stay up names a longer one, such as `--idle 86400`
  ([serve](../serve.md)).

## Fixed

- **Every writer takes the writer lock.** `embed` and `model <id>` wrote vectors, and the `serve`
  poll wrote the graph, without `writer.lock`, so a detached `update` could write the same files
  meanwhile and `status` reported no refresh. `embed` and `model <id>` now wait for a running
  refresh the way `update` does, and a `serve` poll that finds one skips its cycle
  ([keeping fresh](../keeping-fresh.md#background-priority)).
- **Rows a sibling worktree can lend are no longer counted as owed.** A reader weighed them against
  its budget and could start a detached `update` for rows it only had to copy, and the embed meter's
  total counted them as work. Both now borrow first and count only the rows that must be embedded.
