# zerograph 0.6.4

The release notes for the GitHub release page. The why behind each change is in the docs each line
links to.

## New

- **Background priority for work nobody waits on.** The detached `update` that a git hook, a reader
  over its budget or the MCP `reindex` and `switch_model` tools start, and `watch`, run in the
  background band: macOS's `PRIO_DARWIN_BG`, nice 19 with the idle I/O class on Linux, and
  background mode on Windows. `ask`, `build`, `update`, `embed`, `model` and `serve` keep normal
  priority. A foreground `update` that finds a background one holding the store waits for it; `ask`
  never does ([keeping fresh](../keeping-fresh.md#background-priority)).
- **The skill is `zerograph`.** `install-agent --claude` and `--codex` write it to
  `skills/zerograph/SKILL.md`, stamped with the release that wrote it as `metadata.version`, and with
  a section on what keeps the index fresh and how to pay owed vectors without blocking a turn. The
  `repo-query` skill an earlier release wrote is removed; an edited one is left and named
  ([install](../install.md)).
- **`embed_skip` keeps a file in the graph and out of the vectors.** Globs in `zerograph.toml`
  whose files keep their nodes, edges and lexical rows but get no vectors: generated code,
  migrations, mocks. A paraphrase no longer finds them; `impact`, `trace` and an ask by name do
  ([configuration](../configuration.md#files-without-vectors)).
- **`embed_model = "<hub id>:<variant>"` picks a quantised export** of the same model, such as
  `onnx-community/embeddinggemma-300m-ONNX:q4` (a 197 MB download against 1.2 GB). A variant is a
  model of its own to the store, so switching re-embeds every row once
  ([embeddings](../embeddings.md)).

## Changed

- **`resources = "balanced"` takes 40% of the logical cores, up from 30%.** Four threads on a
  twelve-core machine rather than three: a whole-store `build` of the bench fixture read 521.1 s at
  a 396% peak against 674.3 s at 301% ([configuration](../configuration.md#resources)). `low` and
  `full` are unchanged.

## Fixed

- **`install-agent --claude` keeps a matcher you narrowed.** A re-run replaced zerograph's hook
  entries whole, so a `matcher` a repository had changed on purpose (PreToolUse without `Bash`, say)
  went back to the default on every upgrade. The hook script now records the version and the
  matchers it was installed with; a re-run moves a matcher it wrote to the current default and keeps
  any other.

## Before upgrading

- **Hooks that run `update --no-dense`** leave every new row without a vector, and a paraphrase
  misses them. Drop `--no-dense` from them: the embed now runs in the background band, and the
  first dense `update` pays every row owed so far.
- **Re-run `install-agent`** to get the renamed skill. Anything that names `repo-query` — a
  `CLAUDE.md` line, a settings permission — should name `zerograph`.
