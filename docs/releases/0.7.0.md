# zerograph 0.7.0

The release notes for the GitHub release page. The why behind each change is in the docs each line
links to.

## Breaking

- **`zerograph watch` is removed.** It ran the same poll as `serve` without answering anything, and
  every MCP tool now refreshes before it answers, so it was one more process per worktree and one
  more writer. A script or service that starts `zerograph watch` now fails with an unknown-command
  error: start `zerograph serve` instead, which polls the tree between questions with the same
  `--every` and `--batch`. `serve` exits after `--idle` seconds without a question (30 minutes by
  default), so a poller meant to stay up names a longer one, such as `--idle 86400`
  ([serve](../serve.md)).
- **`install-agent` writes no git hooks, and removes the block an earlier release wrote.** The
  `post-merge`/`post-checkout` block lived in the common `.git/hooks`, so every `git worktree add`
  started a full embed. A re-run deletes the block under either marker name and keeps the rest of
  each hook file; a file left with only its shebang is deleted. Every read already refreshes, and
  `serve` catches up when it starts. Git hooks remain an option, written by hand
  ([keeping fresh](../keeping-fresh.md)).
- **The session hook no longer runs a binary from the checkout it starts in.** It used
  `<checkout>/node_modules/.bin/zerograph` when nothing else was found, so a cloned repository that
  committed one got it spawned as soon as a session started there; the Claude Code mod also tried
  `target/{release,debug}` under the checkout. The hook and the mod now take the binary from
  `ZEROGRAPH_BIN` or `PATH` only. A project that installs zerograph as a dev dependency and has no
  global install sets `ZEROGRAPH_BIN` to that binary's absolute path ([install](../install.md)).
- **The `serve` socket moved to `~/.cache/zerograph/sock/<hash>.sock`**, the hash of the canonical
  checkout path, from `.zerograph/serve.sock` or the temporary directory for a deep checkout. One
  rule now holds for every checkout depth and every `$TMPDIR`, which two processes of one user could
  disagree on. The private `$TMPDIR/zerograph-<uid>/` is the fallback only when the path would not
  fit in `sun_path` or there is no absolute home directory. `zerograph status` prints the socket it checked,
  and `status --json` carries it as `serve.socket`, for a tool that looks for a server on its own
  ([serve](../serve.md)).

## New

- **A new worktree borrows its vectors from its siblings.** A vector depends only on the model and
  the row's text, so a dense sync looks the rows it is missing up by text hash in the other
  worktrees' stores (`git worktree list`) and embeds only the misses: a cold `update` beside a
  built checkout borrowed 5118 rows and embedded 90. A sibling is read under a try-lock of its
  writer lock and never written; one with another model or width, a held lock, or a torn pair lends
  nothing. Borrowed vectors are near-identical to fresh ones, not bit-identical
  ([keeping fresh](../keeping-fresh.md#borrowing-from-sibling-worktrees)).
- **The session hook builds a checkout that has no index**, in the background, when the checkout
  opted in: it holds the installed hook or a `zerograph.toml`, or its main worktree does. With an
  index, the `serve` the hook starts catches up as it starts; with `ZEROGRAPH_HOOK_SERVE=0`, a
  detached `update` does it instead ([keeping fresh](../keeping-fresh.md#the-session-hook)).
- **A store records the release that wrote it.** `manifest.json` carries `release`, `status` shows
  it, and a store a newer release wrote has a `newer_grammar` state of its own, which the Claude Code
  mod displays ([commands](../commands.md)).

## Changed

- **With no `--repo`, the root is the top of the git checkout** (`git rev-parse --show-toplevel`; a
  worktree is its own root), else the nearest directory above that holds a `.zerograph/`, else the
  current directory. A read where no store exists no longer creates `.zerograph/`: it answers from
  nothing and says `zerograph build` builds it. The walk skips every directory below the root that
  has its own `.git`, so nested worktrees, clones and submodules stay out of the index
  ([configuration](../configuration.md)). The session hook resolves the same root, so inside a git
  checkout it asks about the top level whatever subdirectory the session is in
  ([keeping fresh](../keeping-fresh.md#the-session-hook)).
- **The Claude MCP server is registered once per checkout.** `install-agent --claude` registers it
  at local scope for each checkout `git worktree list` names, each with its own `--repo`, and prunes
  from `~/.claude.json` the entries it registered for a checkout that no longer exists. A
  `zerograph` entry at user scope or in a tracked `.mcp.json` is left alone: only the local entry is
  replaced, and a note says when another scope holds the name ([MCP server](../mcp.md)).
- **The Claude Code mod reads files instead of polling `status --json`.** Every 10 s it reads
  `background.log` and stats the socket the last report named; the full report runs at session
  start, every 5 minutes, once after a refresh ends and after `/zerograph`
  ([install](../install.md#claude-code-status-mod)).

## Fixed

- **Windows: the session hook takes a `zerograph.exe` before npm's `.cmd` shim, and a call through
  the shim that runs out of time ends the whole process tree.** The shim needs `cmd`, which expands
  `%NAME%` in the repository path, and a timeout killed `cmd` and left `zerograph` running. The
  Claude Code mod prefers the `.exe` the same way and runs a `.cmd` through `cmd` from the shim's
  own directory ([install](../install.md#claude-code-status-mod)).
- **`import-legacy` takes the writer lock** and refuses a store a newer release wrote, like every
  other writer.
- **The printed Codex hooks block quotes the hook path.** A checkout directory whose name held a
  `'` broke out of the quoting once pasted into `~/.codex/hooks.json`; the path is now quoted for
  the shell, and with double quotes on Windows, where `cmd` reads no single quote as quoting.
- **A `serve` started by 0.6.4 can be stopped after the upgrade.** It listens at the old socket,
  where no client of 0.7.0 looks, and writes without the writer lock. `zerograph stop` now sends the
  stop line there as well, and a new `serve` does so as soon as it binds, on a thread of its own: a
  busy old server can take up to 310 s to read it, and meanwhile the new one answers as `--stale`
  does and writes nothing. A deep checkout's old socket is looked for under this process's
  `$TMPDIR` and under `/tmp/zerograph-<uid>/` ([serve](../serve.md)).
- **An older release no longer writes over a newer store.** It answers read-only and prints one line
  naming both generations; `update`, `build`, `embed` and the model switch refuse to write. `ask`
  reads the manifest again before it writes, whether or not it could take the writer lock, so a
  newer `update` that saves in between is not stamped over ([commands](../commands.md)).
- **Every writer takes the writer lock.** `embed` and `model <id>` wrote vectors, and the `serve`
  poll wrote the graph, without `writer.lock`, so a detached `update` could write the same files
  meanwhile and `status` reported no refresh. `embed` and `model <id>` now wait for a running
  refresh the way `update` does, and a `serve` poll that finds one skips its cycle
  ([keeping fresh](../keeping-fresh.md#background-priority)).
- **Rows a sibling worktree can lend are no longer counted as owed.** A reader weighed them against
  its budget and could start a detached `update` for rows it only had to copy, and the embed meter's
  total counted them as work. Both now borrow first and count only the rows that must be embedded.
- **An answer after an edit no longer reads every sibling's whole vector store.** Rows from a fresh
  edit exist in no sibling, yet each such answer listed the worktrees and loaded each sibling's
  vectors. The reader's budget clock now starts before the borrow, a sibling's metadata is matched
  before its vectors are read, and a sibling that lent nothing is not read again until its vectors
  change.
- **The session hook's in-process refresh stays inside its 5 s timeout.** Every call the hook waits
  on gets `ZEROGRAPH_READER_BUDGET=2`, or a smaller value the environment or `zerograph.toml` sets,
  and a refresh that would not fit goes to a detached `update` instead of being killed
  ([keeping fresh](../keeping-fresh.md#the-session-hook)).
- **The Codex hook path survives removing the worktree it was installed from.** The path
  `install-agent --codex` prints is the main worktree's copy, written there when the main worktree
  has none.
- **Worktree notices.** The build notice no longer promises "a couple of minutes" and says that a
  worktree beside a built one borrows its vectors; the docs say each worktree keeps its own store
  and that an APFS clone stops sharing the graph at its first refresh
  ([keeping fresh](../keeping-fresh.md)).
- **A git call from a hook's environment finds the right checkout.** The root lookup, the worktree
  list and the git-hook cleanup inherited `GIT_DIR` and `GIT_WORK_TREE`, so an `update` run by a hook
  manager could take the current directory for the root and build a partial store there. They now
  clear those variables, as `changes` already did.

## Before upgrading

- **Set `ZEROGRAPH_BIN`** where zerograph is a project dependency and not on `PATH`, or the session
  hook and the mod find no binary. A `PATH` entry inside the checkout — `node_modules/.bin` added by
  direnv or an `.envrc` — is now skipped without a word, so a checkout that relied on one needs
  `ZEROGRAPH_BIN` set to the binary's absolute path. The mod's `binary` option takes an absolute
  path or a bare name, which means the `PATH` lookup; a relative path is ignored.
- **A store built in a subdirectory of a git checkout** by an earlier release is no longer read by
  the session hook, which asks about the checkout's top level as the CLI does. Build at the top
  level (`zerograph build` from anywhere in the checkout) and delete the old `.zerograph/`.
- **Re-run `install-agent`**: it removes the git-hook block and registers the MCP server for every
  worktree.
- **Replace `zerograph watch`** in scripts and services with `zerograph serve --idle <seconds>`.
- **A running 0.6.4 `serve`** is sent the stop line by the first `zerograph stop` or
  `zerograph serve` of 0.7.0; otherwise it runs until its own `--idle` timeout. One that does not
  leave is named on stderr and has to be ended by hand ([serve](../serve.md)).
